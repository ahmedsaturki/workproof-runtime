# Ecosystem Roadmap V2 — 2026-09-21

## North star
A self-hosted digital-work ecosystem where a bounded outcome becomes durable work, real execution, independent verification, recovery, and portable proof.

## Kernel
- Work Object
- Outcome Contract
- Capability Registry
- Effect Ledger
- Verification Fabric
- Reconciliation / Recovery
- Evidence / Proof Bundle
- Risk Policy

## Capability families
1. Research & discovery
2. Web / browser
3. HTTP / API
4. Files / documents
5. Data transformation
6. Git / GitHub
7. Database
8. Email / messaging
9. Publishing
10. Local execution
11. Maps / location data
12. Business-system adapters

## Product surfaces
- CLI
- local Studio
- REST API
- SDKs
- worker runtime
- pack registry
- audit/proof viewer
- CI integration

## Interoperability
- MCP adapter: tools into the capability fabric
- A2A adapter: agents into the work fabric
- OpenTelemetry adapter: external telemetry into evidence

## Ecosystem objects
Every public extension should have:
- manifest
- version
- permissions
- operations
- schemas
- verifier/reconciliation strategy
- tests/fixtures
- compatibility metadata

## Growth loop
Build capability → run work → collect evidence → verify outcomes → capture failures → improve routing/recovery → publish stronger packs.

## Guardrails
No public marketplace before the kernel and benchmark are reliable. No broad autonomous claims. No irreversible external writes without policy/approval controls.
